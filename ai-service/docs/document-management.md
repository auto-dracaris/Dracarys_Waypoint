# AI document management and ingestion

Implemented entirely inside `ai-service`. Dispatcher UI and NestJS remain unchanged.
The UI can later call these FastAPI routes directly with the user's bearer token.
No document-management tools are exposed to the conversational agent.

## Responsibilities

FastAPI receives PDFs/UTF-8 text, validates content and access scope, preserves
originals, and creates a version and ingestion job in one PostgreSQL transaction.
The API does not wait for embeddings. A separate process polls durable jobs,
extracts page-aware chunks, obtains dense Gemini embeddings, and writes dense/BM25
points to Qdrant. No Redis, Celery or additional storage service is introduced.

The PostgreSQL catalog is authoritative for approval, current version, deletion
and role/depot scope. Qdrant is the search index. Hybrid search merges 20 dense and
20 BM25 candidates using RRF, checks the returned candidates against the catalog,
and supplies at most three permitted chunks with source/version/page citations.
Scope is checked in both the vector query and catalog when authentication is enabled.

## Local setup

Run these commands from `D:\Git\Dracarys_Waypoint\ai-service` after manually starting
your infrastructure. Preserve the existing ignored `.env`; do not overwrite it.

```powershell
uv sync --locked
uv run python -m app.storage.conversations
uv run python -m app.storage.knowledge
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --loop app.core.runtime:event_loop --reload
```

In another terminal, from the same directory:

```powershell
uv run python -m app.ingestion.worker
```

`--once` processes at most one available job, useful for local checks. The compatible
event loop is needed for asynchronous psycopg on Windows. Both schema commands are
explicit and repeatable; the API does not create tables automatically.

Configure `AI_DATABASE_URL` using the AI PostgreSQL credentials from `infra/.env`
and `AI_QDRANT_API_KEY` using that file's Qdrant key. Keep credentials out of chat.
Configure `AI_GEMINI_API_KEY`, `AI_EMBEDDING_MODEL` and `AI_EMBEDDING_DIMENSIONS` before
uploading. `AI_GEMINI_MODEL` is optional for cited excerpts without generated answers.
Provider/model quality still requires evaluation with your real documents.

The embedding adapter supports both Gemini embedding model families. For
`gemini-embedding-2` (including preview), each chunk is a separate Content entry,
with retrieval instructions in the text rather than the unsupported task_type field.
`gemini-embedding-001` keeps its task_type configuration. Do not mix embedding
spaces when changing models; reindex the corpus in a matching collection.

New settings, with defaults:

| Setting | Default | Purpose |
| --- | --- | --- |
| AI_DOCUMENT_STORAGE_PATH | data/documents | Private original file directory |
| AI_INGESTION_TIMEOUT_SECONDS | 300 | Maximum processing time per attempt |
| AI_WORKER_POLL_SECONDS | 2 | Poll interval while no jobs are available |
| AI_WORKER_MAX_ATTEMPTS | 3 | Automatic attempt limit per job |
| AI_CHUNK_SIZE | 1200 | Chunk size in characters |
| AI_CHUNK_OVERLAP | 150 | Character overlap, less than half the chunk size |
| AI_EMBEDDING_DIMENSIONS | 768 | Provider-supported dense vector length |

Upload snapshots model, dimensions, chunking and collection in its processing recipe;
retries use the same recipe. Keys/tokens are never part of the stored recipe.
Changing embedding model/dimensions needs a matching collection and re-upload of
documents. Restart the API and worker after configuration changes. Old versions
remain immediately unavailable once replaced, even while the new version is a draft.

## HTTP contract

Base path: `/api/v1/documents`. UUID identifiers are generated by the service.
Development Swagger: `http://127.0.0.1:8000/docs`.

| Method/path | Purpose |
| --- | --- |
| POST /api/v1/documents | Upload a new draft; returns 202 with document/version/job IDs |
| GET /api/v1/documents?page=1&limit=20 | Paginated current documents, status and approval |
| GET /api/v1/documents/{id} | Metadata and version history |
| GET /api/v1/documents/{id}/file?version=1 | Download the private original version |
| POST /api/v1/documents/{id}/versions | Upload a new draft version and invalidate the old one |
| POST /api/v1/documents/{id}/approve | Approve a specific ready current version |
| POST /api/v1/documents/{id}/retry | Queue a new job for a failed current version |
| DELETE /api/v1/documents/{id} | Revoke access immediately and queue physical cleanup |
| GET /api/v1/documents/jobs/{job_id} | Processing state, attempt count and safe error code |

Uploads use multipart fields `file` and `metadata`. Send a UUID `Idempotency-Key`
header; preserve that key when retrying the same upload. Reusing it for different
content, metadata or actor returns 409. Server-generated storage keys are never
accepted from clients. Example metadata field:

```json
{
  "title": "Store ordering terms",
  "allowed_roles": ["store_manager", "dispatcher"],
  "depot_ids": [1],
  "citation_url": "https://example.com/terms"
}
```

The citation URL is optional metadata; it is never fetched or crawled. Supported
roles are `store_manager`, `dispatcher`, `driver`, `loader`. Approval/retry bodies
are JSON, for example `{"version":1}`. Approval requires the current ready version;
queued, processing, failed and outdated versions return 409.

## Lifecycle and recovery

Version status: queued -> processing -> ready, or queued/failed after an error.
Ready content stays unpublished until approved. Job state: queued -> running ->
done, or queued/failed after an error. `indexed` in Qdrant indicates completed
index writes; it never grants approval. Partial writes cannot pass catalog checks.

Workers claim jobs with PostgreSQL row locks and renewable 120-second leases.
Heartbeat runs every 30 seconds. Expired jobs are reclaimable after a restart;
stale lease owners cannot publish catalog state. Errors retry after 10 seconds up
to the configured maximum. Exhausted crashed jobs show `worker_interrupted`;
other processing failures show `processing_failed`, without provider exception text.
Worker failure logs include the job ID and exception class, without raw error messages.
Manual retry creates a new bounded-attempt job. Point IDs are deterministic across
retries. Cleanup only removes older versions; it cannot remove a newer replacement.

Deletion hides the source immediately; the worker removes points across recorded
collections and all original versions. If cleanup fails permanently, repeat DELETE
to queue another cleanup job. Tombstones and metadata remain to prevent stale jobs
from restoring access. Retention/purge policies are deferred. Replaced originals
remain available to management until deletion for reviewing version history.

## Access and deployment limits

`AI_AUTH_ENABLED=false` allows local document-only chat to bypass identity and
role/depot filtering. It does not bypass document management: management always
forwards the bearer token to the existing NestJS `/auth/me` endpoint and requires
a verified dispatcher role. Bind locally; production rejects the chat bypass.
This implementation treats dispatcher management as global; finer management
permissions must be agreed before deployment. End-user document access still uses
the verified role and depot. No NestJS permission code is changed.

Originals are private filesystem files, not publicly mounted assets. API and worker
must use the same persistent storage directory. Container replicas need a shared
writable volume owned by UID 10001; separate private container disks are insufficient.
For the initial local deployment, a shared folder is sufficient. Back up originals
and AI PostgreSQL together. DB-failed uploads remove their temporary file; hard crashes
between filesystem writes and DB registration may leave orphans for later housekeeping.

Limits: files 20 MiB, total multipart body 21 MiB, PDFs 200 pages, extracted text
500,000 characters, at most 600 chunks. No OCR, URL crawling, malware sandbox or
untrusted arbitrary-file parsing is included; this first implementation is for
trusted operator uploads. Gateway, tracing and business tools remain deferred.

## Verification

```powershell
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
```

Real PostgreSQL tests are opt-in via `AI_TEST_DATABASE_URL`; they create and drop
unique temporary schemas and do not touch existing tables. The additional HTTP/worker/
hybrid-index test requires `AI_TEST_QDRANT_URL` and `AI_TEST_QDRANT_API_KEY` and uses
a disposable collection. Without integration settings, five tests skip.
All checks use synthetic embeddings; they are not evidence of live Gemini quality
or real-document answer accuracy. Local verification passed 101 tests with the
existing PostgreSQL and Qdrant services, including the complete managed lifecycle.
